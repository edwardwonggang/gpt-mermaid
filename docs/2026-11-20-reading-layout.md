# 组件阅读布局风格

用户要求以参考图的阅读效果调整整个组件，授权分析、实施、测试和推送。此次保留字体大小和语义关系，将布局评价从“连得对、面积小”扩展到“主流程连续、分支均衡、终点靠近主流程、空白有用途”。

## 证据与根因

相同源码、字体、运行库的单变量对照：

| 节点放置 | 包络 | 视觉结果 | 独立几何 |
| --- | --- | --- | --- |
| 旧状态默认 | 509×975 | INIT/DONE靠左，WAIT与POS横跳192 | 通过 |
| BK BALANCED | 515×975 | 起点回分支之间，终点回中部 | 通过 |
| LINEAR_SEGMENTS | 472×997 | 窄但终点仍偏左，不应因面积选它 | 通过 |
| NETWORK_SIMPLEX | 不采用 | 固定端口回执出现分数偏移和斜段 | 拒绝 |
| 均衡放置＋模型内刚性压缩 | 515×837 | 主流程集中、分支平衡、层间留白收紧 | 通过 |

证据在`output/reading-layout-20261120/placement-experiments.json`、完整SVG/PNG和`reading-metrics.json`。不是改变显示缩放或缩小字号。旧FLOW上游默认已经使用BALANCED，自建状态模型缺失该配置；只检查端口、交叉和宽高上限无法发现阅读重心问题。

## 统一策略与图种职责

`src/layout-style.js`统一管理阅读策略ID、节点/通道净距、可见引线、圆角及均衡节点放置。`runtimeLayoutOptions`生成各图种适配参数，禁止把全局nodeSpacing/rankSpacing无差别交给所有图种。

| 图种 | 统一的部分 | 需要保留的语义 |
| --- | --- | --- |
| flow/state | 均衡分支、清晰主方向、文字可读、回路不抢主流程 | flow安全切口折返；state独立端口、标签两段与复合状态 |
| ER/class | 字体、主题传播和真实轮廓检查 | 属性列、成员分区、基数/继承/组合端点 |
| C4 | 字体主题、清晰边界及关系归属 | 系统容器包含关系、完整expected边 |
| sequence | 配置传播与文字清晰度 | 参与者列、消息时间顺序、激活条与自调用 |
| Gantt/统计等 | 配置来源和显示生命周期 | 时间轴或坐标轴，不套状态机层级 |

14px状态文字和13px条件文字保持既有默认；当前未扩展任意fontSize到所有图种的CSS支持。

## 从硬约束到阅读选优

候选仍先检查语义身份、轮廓接触、独立端口、独立箭头、法向可见直段、避障和交叉。硬约束失败的候选不能因更小或更对称获胜。

合格候选继续比较：

1. 返回关系的通道分侧与独立性。
2. 无反馈结构图中最长链关系的横向偏移。
3. 分支源与下游分支重心的距离。
4. 无反馈终点与前驱的横向距离。
5. 面积和弯折。

这些量按节点中位尺寸归一化。主链依据结构深度，反馈依据原业务图DFS，不能用“成功/失败”、状态名或图名匹配业务意义。不能声称结构算法知道用户所有业务主路径。

## 空白压缩的约束

`src/state-spacing.js`在绘制前统一变换模型主轴坐标：

- 所有状态、条件标签、注释占位和路径使用同一个单调映射。
- 对象覆盖的坐标组刚性平移，框内距离和尺寸严格不变，文字不缩放。
- 框外空白受端点引线、目标箭头、圆角、框间净距和并行通道间距约束。
- 同坐标的线段一起映射，不能单独挪标签或某条回路线。
- 压缩结果重新执行原只读约束；未通过则保留原候选，不以更小掩盖冲突。

曾发现仅设“最小框高”会被跨区域约束拉伸框内端口，导致标签与线断开；因此必须使用刚性坐标组，而非为单个失败标签补偏移。数值统一到1e-6以保持重复压缩稳定。

## 配置传播

原`resolveConfig`把旧生成的全部themeVariables当作显式覆盖继承，导致切换preset/字体不生效；初始化缓存又遗漏顶层字体。新实现用私有WeakMap追踪显式主题覆盖，旧派生值每次按preset与字体重新生成，用户显式覆盖继续保留。

公开`configure()`返回重新归一化的独立快照，恢复快照后仍能切换字体。初始化缓存直接使用完整initialize对象，不再维护一个容易漏字段的手写摘要。浅色→深色→浅色和字体轮换均读取最终computed结果。

## 验收

运行目录为独立库根：

```sh
rtk npm test
rtk npm run check
rtk npm run test:api-types
rtk node scripts/verify-package.mjs
rtk node scripts/verify-runtime-integrity.mjs
rtk node scripts/verify-ci-coverage.mjs
rtk zsh -lc 'PLAYWRIGHT_BROWSERS_PATH="$PWD/.ms-playwright" node test/e2e.mjs'
rtk zsh -lc 'PLAYWRIGHT_BROWSERS_PATH="$PWD/.ms-playwright" node test/webkit-mobile.mjs'
```

原例保留7节点、10业务关系、9标签、19显示段、38端点和10独立箭头，新增最终SVG阅读检查：≤550×880、14px状态文字、起点距分支重心<60、终点距前驱<85、WAIT到POS横移<140。阈值只用于固定原例，不是算法按名称定制；改名、两字体和四方向变体另验。

两浏览器覆盖100图、454个箭头、124标签、15既有变体、11个状态端口变体；五图种×三次主题/字体切换直接检查computed值。新增单元覆盖配置来源、公开快照恢复、主干/分支/终点评分、刚性压缩、旋转与输入不变。

Chromium触摸使用14项原生浏览器输入，WebKit的14项多指状态机是合成事件，不当作真机iPhone验收。复杂非平面类图保留真实unresolved，不承诺任意图零交叉。

## 集成与恢复

主站通过固定提交目录同步库与runtime，两端bundle及离线阅读器同时升级；阅读器正文/目录/身份逐字节保留。真实链路还需核对公开资源哈希、净化前后几何、复制/重试/慢下载/离线及查看器手势。主站有其它脏改动，只提交本任务内容。

回滚固定vendor引用和成对reader HTML/manifest后重建两端，不清认证、会话或知识正文。公开API与加载/执行预算沿用既有契约；无需重启用户客户端。
