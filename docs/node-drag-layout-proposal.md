# 单节点拖动与全图自适应布局方案

状态：暂不推进，未实施。用户反馈复杂度较高；后续只有用户再次明确要求时才进入方案选择和实现。调研日期：2026-11-17（北京时间）。本次源码核对基线：`ef5ab85`。

本次展示的8倍截图是静态图局部放大，不是拖动节点后的效果。现有产品仍只有整图平移、缩放和自动折返；本文件仅保留调研备查，不新增编辑模式、节点拖拽或位置存储。

目标是让用户移动一个节点后，其余节点、连线、端口、标签和画布共同调整，同时保留原有图形风格与逻辑关系。**“整个图自动调整”意味着对整图验证和求解，不要求每个节点都发生位移。**

建议优先评审“保留现有 SVG 绘制，增加独立编辑场景与约束布局事务”的路线。它最有利于保留当前箭头、异形节点、标签和 SVG 导出结果，但仍是架构改造，不能当成给图片增加几个拖拽事件的小修复。具体求解器应在用户确认位置语义后通过小型对照原型选定；当前证据不足以承诺 ELK Layered 能硬锁任意节点。

本次仅阅读源码和联网核验官方文档，没有改动 `src`、`dist`、依赖或配置，没有运行拖拽原型、构建或浏览器测试。下文性能数字均为建议验收目标，外部库能力为文档支持范围，不代表本项目已集成或已实测。

## 1. 决策前必须明确的行为

| 决策 | 方案一 | 方案二 | 本次建议与代价 |
| --- | --- | --- | --- |
| 松手坐标 | 节点精确保留在松手位置，其他节点让位 | 松手位置只表达顺序偏好，算法可吸附到层/网格 | 建议前者，符合直接操作的预期；必须处理多个固定位置的冲突 |
| 已经手动移动的节点 | 持续固定，直到用户解锁/恢复自动布局 | 每次只固定当前拖动节点，其余可再次移动 | 建议持续固定，并显示固定状态；约束可能无解，不能偷偷解除 |
| 自动调整时机 | 拖动时预览受影响边，松手后完成全图求解 | 拖动中持续让整个图跟随调整 | 建议先提供前者；持续全图动画有性能和可预测性成本，另设验收 |
| 编辑入口 | 保留阅读模式，显式进入布局编辑；手机使用全屏编辑 | 默认任意位置都能拖节点 | 建议显式编辑，避免手机滚动、整图平移与节点拖动争抢手势 |
| 保存位置 | 暴露布局状态与回调，由宿主选择存储 | 库默认写浏览器存储 | 建议宿主控制；普通预览不新增存储副作用 |
| 图种范围 | 先验收平坦流程图，再分适配器扩展其他图种 | 首版所有 Mermaid 图种均可编辑 | 建议分阶段，并在 UI/API 明示能力；第一阶段完成不能宣称全图种完成 |

这些选项尚未获得用户选定。以下详细方案以“明确编辑模式、松手位置固定、松手后全图求解、宿主负责保存”为待评审基准。若选择层序偏好或完整图编辑器，布局接口、交互文案和验收判据必须一起改。

## 2. 改动前影响分析

### 2.1 谁依赖将被修改的对象

| 对象 | 当前调用方、订阅方或观察方 | 不能忽略的依赖 |
| --- | --- | --- |
| `record.stage`、`record.image` | `zoom()`、`bindMotion()`、`viewer()`、`closeViewer()`、`ResizeObserver`、实验页的原始尺寸操作 | 全屏直接搬移同一 stage；缩放直接写 image 尺寸和 transform；公开类型将 image 定义为 `HTMLImageElement` |
| `record.result` | SVG 下载、PNG 复制、尺寸适配、外部 API 消费者 | 它是导出和显示共用的已提交结果；只移动屏幕节点而不更新它会导出旧图 |
| `renderSvg()` 和临时 `graph` | `factory.js`、`createUi()`、公共 `renderSvg()` | 目前每次重新解析 Mermaid，流程图结构只存在于单次渲染任务中，没有编辑状态 |
| SVG 节点、路径与标签 ID | `flowGeometry()`、端口整理、真实轮廓贴边、`placeEdgeLabels()`、共享箭头裁线 | 依赖结构化 ID 关联，不能从文本或拼接 ID 猜关系 |
| 几何后处理 | 自动折返、避障、方向着色、marker 克隆、线杆裁切 | 当前服务于一次生成；多次编辑不能直接累积执行所有副作用 |
| 源码和布局记录 | `copySource()`、将来的恢复/撤销 | Mermaid 源码不包含这套自由坐标；复制源码和保存编辑布局是两件不同的事 |

### 2.2 改变哪些性质

- **结构和可见性**：编辑模式需要可命中的内联 SVG 层；现有 `<img>` 的节点无法直接接受页面事件。静态 `image` 兼容属性仍应保留，不能无声改成 `SVGElement`。
- **时序**：从“一次解析、布局、生成图片”变成“指针预览、异步求解、校验、原子提交”。旧结果晚到必须被丢弃。
- **状态和数据格式**：新增结构化场景、位置约束、布局版本、撤销事务及可选布局存档。业务语义源仍是原 Mermaid。
- **坐标契约**：明确 SVG 世界坐标、节点中心、布局器坐标与屏幕坐标之间的转换；缩放/滚动不能改变存储的位置。
- **安全边界**：SVG 进入页面 DOM 后继续使用现有净化白名单和唯一 ID，不能因需要交互放开 `foreignObject`、脚本或远程资源。

### 2.3 哪些既有功能可能变样或失效

- 首次加载/冷启动：编辑器若默认启动求解器，会给所有只读图增加解析和下载成本。
- 空图、单节点、不支持图种、元数据缺失：必须明确无可编辑节点或不支持，不能破坏原图展示。
- 报错、离线、求解超时：保留上次已提交布局；不能只更新节点、不更新边后宣称成功。
- 后台标签页、快速连拖、组件销毁：后台暂停或旧 Worker 回包不得覆盖新的布局；销毁后不得写回 DOM。
- 手机和窄屏：纵向页面滚动、双指缩放、单节点拖动、全图平移冲突；需要独立手势状态机。
- 全屏与内联切换：同一 stage 被移动，指针捕获、坐标转换、摄像机和选中状态都要一致。
- 导出、复制和撤销：SVG/PNG 必须反映同一已提交布局；“复位视图”不能顺带清除用户位置。
- 主题、字体、源码变化：节点尺寸或 ID 变化会使旧位置/路由失效；不能用相似文字自动迁移布局。
- 多实例/多端：同一页面多张图不得共享编辑状态；跨标签页/跨端保存只有宿主接入时才存在，需版本冲突处理。
- 已折返图：再次调用无约束折返会覆盖用户放置结果；不能把自动折返当成拖动后的必跑步骤。

### 2.4 如何证明没有波及

必须保留现有静态回归，并新增第 10 节的状态、几何、导出和手势矩阵。验证组合包括纯布局输入输出、真实已挂载 SVG 几何、固定视口截图与局部放大像素；不能以“拖动事件触发”或“图重新渲染成功”作为完成判据。

所有保存、重置和恢复测试使用隔离的布局存储适配器。宿主有真实布局数据时，测试前后比对真实数据哈希；不得拿真实图的布局记录做覆盖性验证。

## 3. 已有架构：证据 → 发现 → 改造路径

| 源码证据 | 已确认的发现 | 对方案的约束 |
| --- | --- | --- |
| [`ui.js` 的 `createRecord`、`renderRecord`](../src/ui.js) 创建 `img` 并使用 Blob URL | 当前图是图片，不是页面里的可交互节点树 | 需要编辑绘制层或几何命中层，不能只监听 img 的节点事件 |
| [`styles.css`](../src/styles.css) 的 `.mgpt-image { pointer-events:none }`；`bindMotion` 在 stage 上捕获指针 | 左键拖动现有行为是移动整张图 | 节点编辑必须在既有 pan 分支前完成明确仲裁 |
| [`render.js` 的 `renderSvg`](../src/render.js) 临时读取 `db.getData()`，返回值仅含 svg、width、height、source | 结构化图和布局状态没有在 UI 中保留 | 需要内部场景结果；对外可通过新编辑控制器提供，避免强制扩展所有只读结果 |
| [`svg-routing.js`](../src/svg-routing.js) 读取 `data-points` 并按 `start/end` 关联节点 | 已有路由整理能力依赖上游已生成的路径，不是完整节点布局器 | 拖动后必须先更新端口/路由输入，不能拿旧路径端点直接继续修补 |
| [`svg-adaptive.js`](../src/svg-adaptive.js) 仅按安全切口折返，拒绝反馈、跨层和子图 | 自动折返不等价于任意位置下的增量求解 | 首次布局可复用，编辑会话必须有明确的折返分带策略 |
| [`svg-labels.js`](../src/svg-labels.js) 根据最终路径选位置，并给碰撞候选高代价 | 标签定位可复用，但“有最低分候选”不等于零碰撞 | 提交前增加零碰撞校验；失败时需要扩大空间或拒绝提交 |
| [`types/index.d.ts`](../types/index.d.ts) 暴露 `image:HTMLImageElement`，没有位置/撤销接口 | 交互扩展属于 API 设计，不是内部实现替换 | 保留旧字段类型，新增可选的编辑控制器及独立布局格式 |
| `svgToPng`、`download` 都读取 `record.result.svg` | 当前导出链路有单一结果源 | 编辑后的 SVG、宽高、布局版本必须在同一提交中更新 |

现有后处理还有明确的一次性副作用：marker 会克隆，部分共享边会移除 `marker-end`，线杆裁切会覆盖 dash，`data-gptm-port-span` 取既有值和新值的最小值，方向颜色会写进 inline style。**不可对已处理的 SVG 无限制重复跑整套流程。** 编辑设计需保存不可变的净化基线、原始 marker/线型/作者样式，提交时从这些语义数据重建本轮派生值，避免越拖 marker 越多、线杆越短、端口尺寸只减不增或颜色锁死。

## 4. 官方资料核验：交互能力和布局能力分开看

资料访问日期均为 2026-11-17。仅使用项目维护方、官方文档或标准正文；以下结论不能替代选定版本的集成验证。

| 候选能力 | 官方明确支持的内容 | 不能据此推导的能力 | 结论 |
| --- | --- | --- | --- |
| ELK `org.eclipse.elk.interactive` | 具体含义由算法解释，通常尽量少改现有布局 [S1] | 任意算法都能把指定节点硬锁到绝对坐标 | 可作稳定性提示，不能作为硬约束证明 |
| ELK Layered `crossingMinimization.semiInteractive` | 从已有 position 推导层内顺序，并保留该顺序；依赖可处理层内约束的交叉最小化策略 [S2] | 精确保留节点 x/y；只设该属性便完成拖拽增量布局 | 适合“保持层序/相对顺序”的路线，具体选项需在运行版本确认 |
| ELK `position` + Fixed | position 用于 Fixed 的预设坐标；Fixed 保持现有布局，不自动调整 [S3][S4] | 固定拖动节点同时自动排布其余所有节点 | 不是本需求的完整方案 |
| ELK Stress `stress.fixed` | 该算法有防止指定节点移动的选项 [S5] | ELK Layered 也支持该选项，或 Stress 自动保留流程层序与现有路由 | 是另一个算法候选，需单独评估布局风格和路由 |
| elkjs | 接收图数据并计算位置，提供异步布局、能力查询和 Worker 接口 [S6] | Mermaid 内部 ELK 已作为本库公共编辑 API 暴露 | 不依赖 Mermaid 的私有全局对象；需要明确适配器和版本能力探测 |
| React Flow / XYFlow | 提供节点位置、拖拽、选择、视口、拖动停止等交互接口 [S7][S8] | 使用 React Flow 就自动具备全图布局、节点避障和现有 SVG 外观 | 自动布局仍需外部引擎，不能替代几何方案 |
| Cytoscape.js + fCoSE | Cytoscape 有位置、锁定、无视图实例；fCoSE 文档明确给出简单节点的固定坐标、对齐和相对位置约束 [S9][S10] | 任意约束必然有解，或复杂父子图均可按相同方式硬锁 | 可先作为原生 SVG 路线的计算后端，不必同时替换显示层 |

fCoSE 的初步原型参数应核对 `randomize:false` 与 `quality:"proof"` 的组合要求，并设置 `fit:false`，避免求解器改动用户视口。它的固定位置约束针对简单节点，不能未经验证扩展到可拖拽容器。其本身采用力导向思路，是否能保持本库流程的层次与局部稳定，仍需用真实分支、长标签和折返样例对照。[S10]

**引擎选择门槛**：任何候选必须在“一个固定节点、两个固定节点、互相冲突的固定节点、长宽不同节点、分支、回边、重复拖动”七类输入上给出可审计结果。读取官方参数表或看到一个演示不能算通过。当前不承诺最优布局、不承诺所有约束都有解，也不把算法失败静默改成软约束。

## 5. 可评审的技术路线

| 路线 | 实现范围 | 优势 | 代价、主要风险与回滚 |
| --- | --- | --- | --- |
| **A：保留原生 SVG，新增编辑场景和布局适配器** | 静态 img 保留；编辑时启用已净化 SVG 层，保留形状/文字/marker；约束求解器只产坐标，既有路由/标签职责扩展为事务 | 最容易保留既有外观、纯浏览器 API、SVG/PNG 同源导出 | 工作量中高，需场景、手势、布局、导出、回归五个完整部分；关闭可选编辑入口即可回到静态链路，布局侧存档保留 |
| **B：新增 React Flow 编辑器入口** | 单独 React 适配入口，映射节点、端口和边，继续接外部布局器；静态 UMD 不强制迁移 | 现成节点交互和视口控制适合继续扩展连线编辑、选择、节点工具栏 | 工作量高；增加 React 依赖和第二套显示/导出映射，异形节点与精细箭头需重建；可停用编辑器入口，但不能把新数据默默塞回旧接口 |
| **C：完整 Cytoscape 编辑器** | 用 Cytoscape 接管显示、交互与模型，布局可选 fCoSE | 适合未来偏图分析或大型关系网络的产品方向 | 工作量高；当前 SVG 外观、标签、复杂形状和矢量导出需要适配验证；其 PNG 导出并不能证明现有 SVG 契约等价 [S9] |

**推荐评审 A，求解器先做 fCoSE 硬位置与 ELK Layered 顺序偏好的对照。** 这不是已确定采用 fCoSE。若用户选择“松手后允许吸附回层”，ELK 的层序路线更值得优先验证；若要求精确松手位置，不能只靠 ELK Layered 的半交互参数交付。

只给 img 叠矩形命中框可用来测命中原型，但它并不形成可维护的编辑产品：节点真正移动时仍需重绘 SVG、同步全部边和标签，矩形还可能误命中异形轮廓和嵌套节点。因此不建议把该原型当成最终架构。

## 6. 路线 A 的职责与数据设计

### 6.1 建立独立的编辑场景

只在进入编辑时创建一个活动场景，避免 101 张实验图同时保留大量活动 SVG DOM。

| 数据层 | 内容与来源 | 生命周期 |
| --- | --- | --- |
| 语义图 | 本轮解析得到的稳定节点 ID、边 ID、source/target、方向、父子关系、线型和标签身份 | 源码改变即重新建立；不保存随机渲染 ID |
| 净化基线 | 上游 SVG 净化后的形状、文字、作者样式、原始 marker 和布局几何 | 只读，供每次提交恢复派生样式 |
| 已提交场景 | 世界坐标中的节点中心、尺寸、端口、边折点、标签位置、固定约束、revision | 下载、恢复、撤销的权威状态 |
| 拖动预览 | 当前拖动节点目标中心、受影响边、临时碰撞反馈 | 指针会话结束即提交或丢弃，不进入持久化 |
| 视口 | pan、zoom、fit 尺度与屏幕锚点 | 与布局分离；复位视图不清位置 |

节点身份使用 Mermaid 的语义 `id`；`domId` 和 `${svg.id}-${domId}` 仅用于当前实例映射，不能作为存档主键。节点模型以中心坐标为约定，布局器若使用左上角坐标由适配器转换。所有坐标有限且在统一世界坐标系内。

不得把 `graph`、DOM 元素和 `record.result.svg` 都作为互相覆盖的独立权威状态。场景提交后生成显示和导出；DOM 是场景的投影。

### 6.2 命中、拖动和视口

1. 编辑 SVG 使用现有净化结果，事件委托命中带稳定映射的 `g.node`；点击节点文字同样选中该节点。需要扩大触摸命中区时，采用独立透明命中形状并保持节点 ID 关联，不能按最近文字判断。
2. 命中后记录“指针世界坐标减节点中心”的偏移，避免一按下节点就跳到指针正中。坐标转换使用 SVG 的屏幕矩阵逆变换，不能只除以 `record.zoom`。
3. 每帧先读当前矩阵，再合并处理最新 pointermove；自动平移或全屏切换后矩阵可能改变，不能永久复用 pointerdown 时的逆矩阵。
4. `pointercapture` 只归属于当前编辑动作；`pointercancel`、`lostpointercapture`、Escape、销毁都进入明确的取消路径。捕获不能绕过浏览器已经选定的触摸滚动行为。[S11]
5. 编辑模式里节点拖动和空白 pan 使用互斥状态。首次移动超过阈值才形成拖动；点击仍可选择。
6. 世界坐标可扩展到原 viewBox 外。拖动中不连续调用 `fit()`；提交更新边界时补偿视口平移，使被拖节点在屏幕上的位置保持稳定。用户主动“适应窗口”才改变整体取景。

保留 `record.image` 的类型和只读预览用途。编辑层使用同一视口变换规则，进入/退出编辑时不同时展示两份图。是否允许内联编辑或限定全屏属于产品决策。

### 6.3 松手后的全图布局事务

建议流程为：

1. 生成不可变输入快照：当前语义图、尺寸、现有坐标、固定节点、目标节点位置、布局版本。
2. 当前节点的新位置成为本次硬约束；其它手动固定节点仍固定。其余节点作为可调整变量，优先减小相对原位置的变化。
3. 在 Worker 或可取消的计算任务中求解。原生 SVG 不传入 Worker，只传数值、ID 和约束。
4. 求解结果以 `{baseRevision, transactionId}` 标识。只允许与当前场景匹配的结果进入校验，旧回包直接丢弃。
5. 对候选整图重建端口与连线，检查节点重叠、边穿非所属节点、标签遮挡、固定位置偏差和逻辑图一致性。
6. 全部通过后一次替换已提交场景、`record.result.svg`、宽高、Blob 预览和撤销记录；失败则保持此前已提交场景，并给出原因。

硬约束与优化偏好必须分开：

- 硬约束：节点/边身份和语义不变；固定节点位置不被算法移动；没有非法非有限坐标；图种要求的包含关系不被破坏。
- 验收约束：不得留下节点重叠、边穿非所属节点或标签覆盖；找不到满足结果时拒绝提交，不能因为“分数最低”而接受碰撞。
- 优化偏好：尽量少移动非目标节点、尽量少弯折和交叉、尽量保留原相对层序。普通边交叉不等同于节点碰撞，密图不承诺零交叉。

方向语义指 source/target 和 marker 起终端不变。用户若把节点拖到前驱另一侧，是否允许出现回向连线，或者必须吸附回合法层，是第 1 节必须确认的决策，不能用交换边端点实现“看起来方向正确”。

### 6.4 连线、端口、标签与后处理

- 先从新节点位置和语义端口重新生成候选路径，再调用路由整理；不能只修改 `g.node transform` 后沿用旧 `data-points`。
- 节点搬移会让原本不相关的边受到障碍影响。拖动预览可只重算相邻边，正式提交必须验证所有边与新障碍集；必要时扩大到整个连通分量。
- 包围盒用于保守避障和空间索引，最终端点必须与所属节点的真实轮廓求交，不能把矩形边界当成所有形状的实际接触点。
- 每次重新计算起点/终点可用端口间距，清除前一版的派生共享标记和端口跨度。共享主干改变时恢复原始 marker，再重新决定共享；每条逻辑边和标签仍单独存在。
- 标签绑定稳定边 ID，沿最终路径定位；保持长文字和多行子变换。若全部候选都发生碰撞，需要扩大路由空间/节点间距后重试一次，仍失败则拒绝提交并保留原布局。
- 方向着色从原始作者样式和新路径方向推导，不能把上次的系统颜色当成作者指定颜色。
- 最终顺序：节点布局 → 端口/路径 → 真实轮廓贴边 → 标签 → 画布边界 → 方向 marker → 线杆裁切 → 净化/校验/序列化。
- 拖动时只预览，正式版本才进行完整 marker 和裁线派生，避免每帧克隆定义或覆盖 dash。

### 6.5 已折返图如何处理

当前自动折返根据初始拓扑和阈值生成分带，没有用户位置约束。编辑时有两种可评审策略：

- **保留分带**：进入编辑时冻结当前带、带内顺序和唯一桥边，拖动仅在当前带调整；跨带拖动明确禁止或另有“移动到另一带”动作。实现范围较清楚，但限制自由拖动。
- **自由编辑**：以当前折返结果为初始坐标，用户位置优先，不再自动执行原折返器；其余节点/连接围绕固定位置重排。需要重新验收整图可读性，也可能产生更大画布。

建议自由编辑作为完整目标，但在算法验证阶段同时展示两种效果让用户选择。不能在每次松手后调用现有 `applyAdaptiveFlowLayout()`，把用户位置悄悄覆盖回自动带。

“恢复自动布局”应是独立、可撤销的操作：解除相应固定位置后重新执行初始布局和安全折返。现有“复位/适应窗口”继续只改变视口。

## 7. 撤销、保存与导出

### 7.1 撤销事务和恢复

一次拖动对应一次历史项，包含被拖节点及所有自动调整节点的位置、约束和相应几何变化；不能把每个 pointermove 记入历史。撤销恢复已提交快照，不重新调用随机/启发式布局器求一个“差不多”的状态。

拟议布局存档字段为 `schemaVersion`、`sourceHash`、`rendererVersion`、`layoutAdapterVersion`、`renderProfileHash`、稳定节点 ID、世界中心坐标、固定状态，以及可选独立视口。它是待评审格式，当前公共 API 尚不存在。

- `sourceHash` 防止把一张图的布局错误套给另一张图；源码变化时拒绝自动恢复，不能按相似标题配对。
- `renderProfileHash` 覆盖影响尺寸的主题、字体等配置；尺寸变化后的恢复必须重新校验。
- 导入时校验版本、ID 集合和有限坐标，不接受 DOM 或脚本作为布局状态。
- 缺省只保留实例内状态；宿主通过布局回调和导入/导出接口决定写文件、浏览器存储或服务端。
- 多端同步由宿主提供 revision 比较；若远端和本地同时改动，不做无条件“最后写入覆盖”。
- `destroy()` 同时取消任务、释放活动 SVG/事件、清理 Blob 和工作线程引用。

### 7.2 保持导出结果一致

当前 SVG 下载和 PNG 复制读取 `record.result.svg`，建议保留这条单一结果链路。

- 输出必须来自最新已提交场景，且 SVG/PNG、宽高、布局版本一致。
- 求解尚未提交时，导出明确等待或提示正在调整；不得静默导出旧图并让用户以为是当前拖动结果。
- 序列化时移除选中框、拖拽手柄、临时辅助线、交互标记与监听器；保留语义图形、文字、连线、marker 和必要样式。
- 世界布局与视口分离：当前缩放或平移不应裁掉导出内容。继续使用现有 PNG 尺寸/像素预算。
- “复制 Mermaid 源码”仍返回原源码；如需跨设备保留手动位置，应另导出布局 JSON。不能暗改 Mermaid 文本加入本库私有坐标并假装通用。
- 双表示只允许一个权威场景：不能让屏幕内联 SVG、隐藏 img 和导出 SVG 各自独立漂移。

## 8. 手机、键盘与图种范围

### 8.1 手机与键盘

建议阅读模式继续允许页面纵向滚动；进入全屏编辑后才由编辑区域接管节点拖动和双指视口操作。节点单指拖、空白单指 pan、双指 pinch 采用清晰状态机；第二个指针到来时取消未提交节点拖动，再进入双指手势。

`touch-action` 必须在手势开始前确定。W3C 明确指出，在进行中的手势里更改 `touch-action` 不会取消浏览器已经选定的滚动/缩放行为，所以“长按之后再把 pan-y 改成 none”不能作为可靠的唯一实现。[S11]

键盘用户可选中节点后用方向键移动、Shift 加大步长、Escape 取消、撤销/重做恢复；未选中节点时继续保持原有视口键盘行为。固定/调整中/失败状态要有可读文本，不能只靠颜色。低动态模式禁用补间动画，但保留相同最终坐标。

### 8.2 分阶段能力表

| 图种或结构 | 建议阶段 | 必须先证明的能力 |
| --- | --- | --- |
| 平坦流程图：链、分支、合并、不同尺寸/异形节点 | 第一阶段正式候选 | 四方向、真实轮廓、硬位置、整图碰撞、端口、标签、撤销与导出 |
| 流程图自环、平行边、双向/圈叉、反馈环 | 第一阶段的显式扩展门槛 | 不能用单一 DAG 假设；箭头语义、重叠、避障和约束冲突分别验收 |
| 多独立组件 | 后续扩展 | 拖动一个组件不无故打乱其它组件；有碰撞才移动必要范围 |
| 折返流程图 | 需先选择第 6.5 节策略 | 带间桥边、方向语义、自由放置或带内限制的明确反馈 |
| 嵌套 subgraph / 跨组边 | 独立阶段 | 父子坐标、容器尺寸、包含约束、拖父随子、跨层端口；不能把子图当普通节点硬锁 |
| C4 | 独立适配器 | 系统边界与人物/容器关系、标题障碍、关系身份、背景文字对比度 |
| ER、class、state | 分图种适配 | 表格/成员合法对齐、基数/UML语义端点、状态嵌套和特殊节点 |
| sequence、Gantt、timeline、pie、XY 等 | 默认只读，另行设计 | 时间、顺序、数值轴或统计语义不适合直接套“普通图节点自由拖动” |

不支持的图继续展示现有静态结果，并明确说明编辑范围。第一阶段只完成候选集合时，产品和最终汇报都必须列出未完成范围。

## 9. 性能与实施顺序

### 9.1 性能策略

- pointermove 合并到 `requestAnimationFrame`，只更新目标节点和必要预览，禁止每次重跑 Mermaid 解析/布局。
- DOM 尺寸批量读取后再写入；字体就绪后测一次，不在每条边上交替强制布局。
- 纯数值求解与路由可移到 Worker；最终真实 SVG 轮廓测量、文字尺寸和序列化仍留在主线程。
- 活动图只允许一个待提交任务；快速拖动时后一次取消或淘汰前一次。elkjs 有 Worker 终止接口，但不能假定取消某次请求便不影响其它任务，需按适配器隔离。[S6]
- 对边和节点使用空间索引过滤障碍候选；正式验收仍检查整图。当前正交路由的网格上限是 `40000`，不能仅调大常量掩盖计算爆炸。
- 编辑资源和求解器按需加载。若新增 Worker 文件，沿现有模块基准 URL 解析并验证 GitHub Pages 项目子路径。
- 大图超预算给出明确失败或“松手后计算”行为，保留最后有效场景；不得退成直线穿框或丢标签。

建议首轮性能目标如下，均待选定设备实测后确认：

| 数据集 | 拖动预览目标 | 松手到已提交目标 | 失败边界 |
| --- | --- | --- | --- |
| 桌面 60 节点、100 边 | 帧耗时 P95 ≤16.7ms | P95 ≤300ms | 超预算保留预览/反馈，取消旧任务 |
| 手机 60 节点、100 边 | 帧耗时 P95 ≤33ms | P95 ≤1000ms | 无长时间无反馈；允许取消并回到已提交状态 |
| 桌面 200 节点、400 边 | 不承诺持续全图动画 | 先测 Worker 内存与耗时后定门槛 | 不因尺寸大绕开正确性校验 |

计时需同时记录设备、浏览器、节点/边/标签数、布局器版本和冷/热状态；单次最快结果不作验收。

### 9.2 实施顺序与停止闸门

1. **用户先选行为与路线**：确认硬位置还是层序偏好、固定位置持续规则、拖动中还是松手后求解、图种范围与保存方式。
2. **约束原型**：只用数值场景对比两种布局适配器，验证固定点、尺寸、冲突与稳定性。未经批准不改现有入口。
3. **一个完整窄链路**：真实流程图进入编辑 → 拖一个节点 → 全图调整 → 通过几何验证 → 撤销 → 导出一致。
4. **能力扩展**：按第 8.2 节逐类开放，未过矩阵的类型保持只读；不能靠额外 if 分支声称普适。
5. **回归与发布**：静态默认行为、类型声明、UMD/ESM/CJS、GitHub Pages 路径、手机手势和导出一起验收。

约束原型若无法同时保住用户位置和零碰撞，应回到已选行为讨论，不能用自动吸附、删除边或隐藏失败凑出“可拖动”。

| D19 | 手机纵向滚动、节点拖、空白pan、第二指加入 | 阅读页不抢滚动；编辑模式动作互斥；双指开始时未提交节点拖动按约定取消；无卡住捕获 |

| D22 | 自环、反馈、多组件、子图与不支持图种 | 支持的逐类通过几何断言；未支持的明确只读并保持原图，没有“部分成功”误报 |
| D23 | 深色主题、长英文、多行、ER属性/类成员回归 | 文字可读性和合法对齐保持；主题改变后尺寸重新校验；静态非编辑图种不受影响 |
| D24 | 桌面/手机不同数据量，后台切回、离线、Worker超时 | 按第9节记录P50/P95、内存和取消结果；正确性不因超预算降级 |
| D25 | 两个图实例及隔离存储适配器并存 | 状态/历史/选中/Worker结果不串图；真实宿主数据哈希不变 |

## 11. 审批范围和可回滚边界

本方案涉及内联 SVG 编辑层、布局场景、异步状态、可选依赖、类型和存档格式，属于需要用户先选定的结构性改造。评审通过之前，不开始迁移、拆文件、安装新运行依赖或替换现有图片显示契约。

建议把编辑能力设为显式启用的独立入口；未启用的静态路径保持既有行为。回滚时关闭编辑入口并恢复匹配的源码/dist版本，保留布局 JSON 供未来恢复，不删除用户源码或存档。若选择路线 B/C，先以独立入口引入，不能为了复用其交互层强制所有 UMD 使用者迁移框架。

待用户选定后，应把第1节决策转成明确的产品契约，再依据约束原型结果确定实现成本。当前不能给出有实测依据的工期，也不能将“已有拖动事件”和“已有布局库”相加当作完整能力已经存在。
